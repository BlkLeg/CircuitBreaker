## 1. What was wrong

The prior review found three things. All three are addressed here.

1. **Nothing was enforced.** Both branches returned `Branch not protected`, and the only ruleset,
   `Main-Branch`, had sat at `enforcement: disabled` since 2026-03-14.
2. **The documented configuration could not be enforced as written.** It named required checks that
   no workflow reports. Enabling it verbatim would have left every pull request unmergeable —
   including the one correcting it.
3. **The documented set was incomplete**, omitting `Backend tests`, `Security Gate`, `Browser E2E`,
   both CodeQL analyses and the docs gates.

## 2. Method

The required-check list was not transcribed by hand. It was generated by parsing every workflow
under `.github/workflows/` for a `pull_request` trigger on `main` or `dev`, reading each job's
`name:`, and expanding matrix templates to their concrete check-run names — so the list cannot
contain a name that no job reports, which is the defect that made the previous configuration
unenforceable.

Two path-related traps were checked for explicitly, because both produce a check that never
reports and therefore a pull request that never becomes mergeable:

- **Matrix jobs.** `browser-e2e` reports `Browser E2E (shard 1/2)` and `(shard 2/2)`, never
  `Browser E2E`. A `browser-e2e-gate` aggregate job now supplies that stable name; it runs
  `if: always()` because a skipped required check counts as *satisfied*, so an aggregate that
  vanished when a shard failed would have turned red shards green.
- **Path filters.** `docs.yml` is filtered to `docs/**`, `mkdocs.yml` and four root files. Its two
  jobs are blocking and would otherwise qualify, but a backend-only pull request never triggers
  them, so requiring either would hang every code change. They are excluded on that ground, which
  corrects the prior review's claim that omitting "the docs gates" was itself a defect.

A third trap was found in the ruleset's own parameters rather than in the workflows:
`require_extra_approval_for_unattributed_changes` was `true` on the inherited `Main-Branch`
ruleset. With `required_approving_review_count: 0`, an "extra" approval is an approval this
repository cannot produce, and a commit carrying a `Co-Authored-By` trailer for an address with no
GitHub account is exactly what triggers it. It is set to `false` for the same reason the code-owner
rule is off — see §3.

## 3. Review model, and what is deliberately absent

`required_approving_review_count` is **0**, and `require_code_owner_review` is **false**.

GitHub does not permit an author to approve their own pull request, and this repository has exactly
one codeowner (EXC-002). Any non-zero approval count, and any code-owner requirement, is therefore
unsatisfiable by the only person able to satisfy it: every pull request would be permanently
unmergeable. The alternative considered was to require the review and grant that same person a
bypass. It was rejected on 2026-09-17: the branch would report as review-protected while every
merge was a bypass event, which is a control that looks enforced and is not — precisely the
condition GOV-15 exists to detect.

**Consequence for SEC-07.** Its stated mechanism is security-owner approval through CODEOWNERS, and
that mechanism does not operate here. `.github/branch-protection.md` now says so in the SEC-07
section rather than implying the gate is live, and
`apps/backend/tests/test_endpoint_policy_inventory.py` asserts that the document states exactly one
of the two states — so the claim cannot silently drift back, in either direction, without a test
failing. What does still gate the policy automatically is the endpoint policy / route-inventory
check inside `Lint`, which is a required status check: an unclassified or silently-changed public
route fails the pull request. That is weaker than SEC-07 describes — it catches undeclared changes,
not ill-advised declared ones — and the difference is SEC-07's open half, not GOV-15's.

## 4. Applied configuration

Two rulesets, identical in rules, differing only in target:

| | `Main-Branch` (id 13901513) | `Dev-Branch` (id 23638197) |
|---|---|---|
| target | `~DEFAULT_BRANCH` | `refs/heads/dev` |
| enforcement | `active` | `active` |
| bypass actors | none | none |
| rules | `deletion`, `non_fast_forward`, `pull_request`, `required_status_checks` | same |
| required checks | 21, `strict` | 21, `strict` |

The 21: `Lint`, `Security Gate`, `Backend tests (shard 1/4)`…`(4/4)`, `Backend coverage gate`,
`Fresh-install migrations`, `Test`, the ten `security.yml` jobs (`Security Suppression Metadata`,
`Trivy Filesystem Scan`, `Trivy Config / IaC Scan`, `Semgrep (SAST)`, `Bandit (Python SAST)`,
`Gitleaks (Secret Scanning)`, `Checkov (GitHub Actions / IaC)`, `Python Dependency Audit`,
`Frontend Dependency Audit`, `Go Vulnerability Scan`), and `Analyze (Python)` /
`Analyze (JavaScript / TypeScript)` from `codeql.yml`.

**The one exclusion: `Browser E2E`.** It is excluded because it is genuinely failing, on both
branches, and was failing before it was required anywhere — shard 2 fails a webkit focus assertion
(`global-navigator … hands focus to the dialog`) and the `monitors-empty` visual baseline. The same
shard fails on `main`'s run of 2026-09-08, before any of this work began, so this is not a
regression introduced here. Requiring a failing check would block every merge including the pull
request that repairs it. The repair is REL-17 (Playwright E2E coverage) and REL-18 (visual
regression); adding the check to both rulesets afterwards is a one-line edit to each.

`Branch not protected` on both.

so the configuration gates a state known to be reachable rather than one merely hoped for:

- `dev-ci.yml` run 35302581320 — `Lint`, `Security Gate`, all four backend shards,
  `Backend coverage gate`, `Fresh-install migrations`, `Test` all green.

- `codeql.yml` run on `0e7531e9` — success, both analyses.

Three of those were red beforehand and were repaired as part of this work rather than excused:
`Security Gate` and `Go Vulnerability Scan` (17 reachable Go standard-library advisories, fixed by
raising the `go.mod` floor to 1.26.8 in `1a66914a`), and `Backend tests (shard 1/4)` (the SEC-07
policy assertion, updated in `0e7531e9`).

## 6. Standing caveat

This file records the live server-side state on 2026-09-18. Repository settings are not in version
control, so nothing in the repository keeps them true: a later settings change can invalidate this
without touching a tracked file. Re-run the two `gh api .../rules/branches/<name>` calls above to
confirm before relying on it, and re-verify the check list after adding, renaming or path-filtering
any job — the generated-not-transcribed method in §2 is the cheap way to do that.
