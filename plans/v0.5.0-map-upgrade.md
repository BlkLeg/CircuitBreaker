## Product intent

Give Circuit Breaker's primary topology workspace the precision, depth and visual
quality of an enterprise operations console. Improve the presentation of the
capabilities already present: live topology, telemetry, monitoring, relationships,
editing, layouts, security signals and map navigation.

The first Operations and Exploration drafts are superseded. Their revised
console-based designs now have separate implementation plans:
[Exploration](../docs/design/2026-09-29-map-exploration-workspace-plan.md) and
[Operations](../docs/design/2026-09-29-map-operations-workspace-plan.md).
They share the approved native console and distinguish existing capabilities
from new local scope and authorized change-feed work. See the
[capability audit](v0.5.0-map-feature-audit.md) for existing behavior.

## Main visual changes

1. **Preserve topology character:** retain current node shapes, device
   silhouettes, branded SVGs, vendor artwork, badges, handles and status
   treatment. The original screenshot was a stale historical reference.
2. **Structured connection walkthrough:** use equipment tiles in an optional
   editor to choose nodes, establish supported connections/relationships and
   review the structured result. **Present Layout** applies the reviewed layout
   to the native map, rendered with its existing visual identity.
3. **Operational hierarchy:** consolidate the existing controls into a compact
   command strip and place health, security and freshness information in a
   coherent situation strip. The full console is hideable and the canvas reclaims
   its space. Keep a small restore control available, including in fullscreen.
4. **Inspection:** recompose the existing selected-node and hover telemetry
   information with strong alignment, source attribution, clear timestamps,
   relationship hierarchy and permission-aware actions. The inspector and hover
   details retain the actual branded node identity; the inspector is separately
   collapsible/hideable without clearing selection.
5. **Analysis:** replace the draft's tiny CPU trace with a dockable telemetry
   workbench. Use calibrated axes, explicit time ranges, detailed sampled traces,
   shared cursor, units, exact values and honest missing-data states. Use the
   existing agent telemetry workbench as a quality floor. Provide expand,
   collapse, hide and restore states; hiding reserves no height.
6. **Finish:** consistent typography, surface contrast, crisp borders, precise
   focus and selection treatment, responsive tool placement and meaningful motion.
   Preserve the real logo and follow active theme tokens in every supported theme.

## Chart contract

- Map charts consume available source histories, rather than fabricate a generic
  series for every entity. Agent telemetry and monitor latency have existing
  history APIs. Generic entity telemetry supplies at most 20 metric rows total.
- CPU and memory percent use fixed 0–100 scales. RX/TX share an appropriate rate
  scale and retain explicit units. CPU and load are not mixed on one scale.
- Middle-pane chart grids and traces fill its width and meet adjacent pane
  dividers. Maintain readable inset labels without insetting the entire plot.
- Timestamp spacing follows actual elapsed time. Show sample cadence/count,
  source, range, last/min/max and exact inspected values where available.
- Preserve gaps and unknowns. Do not interpolate missing spans, connect separate
  sources, invent temperature or claim link capacity is measured utilization.
- Show configured thresholds only when real configuration exists. Mock values
  and traces in the design are clearly labeled illustrative data.
- Short histories retain a useful current-reading surface and explicit
  insufficient-history state.

## Optional interaction extensions

Map-local find-and-center, neighborhood isolation, a minimap, refined semantic zoom,
bounded topology activity and a chrome-free wallboard may complement the visual
upgrade. They are not the main justification or default release scope. Search,
relationship details, fullscreen, grouping and live updates already exist in
related forms, and the shared header already displays recent entity changes.
Scope extensions only after the core visual direction is reviewed.

The 2026-09-29 Exploration and Operations plans select local find/focus,
bounded neighborhood scope, operational aggregation and scoped recent changes
as follow-on mode work. Their explicit packages and acceptance gates supersede
the optional status of those specific items. Minimap, additional semantic zoom,
incident correlation, replay and a separate wallboard remain outside those plans.

## Present Layout contract

- Draft connection editing does not silently change the saved map. Review the
  active map, endpoint identities, supported relationships/types and placements.
- Reuse the existing link command/API mappings. Connection type is not a
  substitute for relationship semantics; reject unsupported endpoint pairs.
- Present Layout validates against the current document, persists reviewed
  relationships, applies layout positions and returns to the familiar renderer.
- Preserve icon sources, branded SVGs, shapes, metadata, annotations, edge
  overrides and nodes unaffected by the workflow.
- Existing APIs persist links individually. Report and retain partial results
  for safe retry; do not claim an atomic transaction or silently show success.
- Hide Console preserves viewport, selection, document state and live updates.
  Console toggles must not trigger a full graph relayout/refit or mark the saved
  layout dirty. Restore the previous panel configuration without a page reload.

## Implementation boundaries

- New modules live under `apps/frontend/src/features/map/` as `.ts` / `.tsx`.
  Introduce them incrementally into existing JSX and avoid a wholesale migration.
- Preserve the canonical document, positions, viewport, selection, annotations,
  filters, renderer choice, permission behavior and edge overrides.
- Existing streams and polling fallback remain the live data foundation.
  Verify update bursts cannot overwrite more recent document state.
- Sigma currently reconstructs its graph and reapplies layout on node/edge
  changes. Incremental graph updates are required before promising stable
  high-frequency large-map interaction; this is an engineering issue, not a
  newly invented feature.
- Keep React Flow and Sigma capabilities explicit. The design does not establish
  renderer parity or measured performance merely by showing a large graph.
- Preserve the user's in-progress viewport/loading changes.

## Release validation

- Review full-size topology and expanded/collapsed analysis views in supported
  themes, with reduced motion, keyboard focus and small-screen layouts.
- Verify real values, axis domains, timestamp spacing, gaps, short history,
  source switching and stale telemetry presentation.
- Verify selection, layout, annotations and overrides survive live updates,
  reconnects, map switching and renderer switching.
- Measure graph rendering and update latency on representative datasets before
  making scale claims.
- Run TypeScript checking, focused behavioral and map interaction tests,
  accessibility checks and the production build for the implemented scope.
