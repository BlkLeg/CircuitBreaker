# npm CLI 04 — Backup and restore adapters Implementation Plan

Date: 2026-09-30. Status: **Active — planned; no task started.**

**Goal:** Provide verified native data snapshots and complete lifecycle recovery points; a failed
backup always prevents activation.

**Architecture:** Reuse the backend snapshot builder and verifier for database/uploads/vault
material, then compose a separate lifecycle recovery manifest for release files, configuration,
units and identity. Snapshot integrity and successful restore rehearsal remain separate evidence.

**Depends on:** 03. Stopped-service capture is implemented here; live gate integration and
transaction commit land in 05. **Roadmap slice:** 5. **Requirements:** NPM-03, NPM-09.

The [design contract](../docs/design/2026-09-30-v0.4.7-npm-cli-design.md),
[ADR 0006](../docs/adr/0006-npm-installer-cli-for-1.0.md) and
[roadmap](./2026-09-30-v0.4.7-npm-cli-implementation.md) control this work. These are implementation
instructions, not evidence that the behavior shipped. All new paths below are proposed.
File lists are the starting scope: record additional integration/test paths before implementing
a task, and keep the package allowlist and native release inventory synchronized.

## Handoff interfaces

These contracts are proposed here; freeze their field-level definitions in the named
schemas/protocol documents before downstream implementation.

| Interface | Contract / consumer |
|---|---|
| Recovery manifest | Versioned component inventory, digests, installation identity, source schema and consistency mode; 05–07 validate before use. |
| `captureRecovery(context)` | Requires operation ID, plan digest, lock context and evidence of stopped/drained writers; returns a verified private recovery reference. |
| `restoreRecovery(reference, context)` | Validates reference and records component checkpoints; requires a current safety point before replacing usable current state. |
| Quiescence evidence | Native stopped-service proof in 04; live write-gate/drain proof added by 05. A caller-supplied boolean is insufficient. |

## Scope boundary

Activation and the durable maintenance gate are in 05. Downgrade/rollback selection is in 06. Docker
lifecycle support requires its own immutable identity and volume recovery evidence before enabling
it.

  trusted paths.

- [ ] **Step 2:** Preserve private staging, atomic snapshot finalization, database checksum and

### Task 2: Make upgrade backup unconditional on actual database connectivity

**Files:**

- Modify: `deploy/setup.sh`
- Modify: `tests/build/test_pre_upgrade_backup.py`

- [ ] **Step 1:** Remove the inactive-PgBouncer shortcut in `run_upgrade`. Probe and use the
  supported snapshot connection; do not invent credentials or claim database health from service
  state alone. Decide the supported direct-database fallback from actual configuration and test it;
  if no supported connection works, refuse with 7 before replacing binaries or running migrations.

- [ ] **Step 2:** Create private backup paths with correct ownership from the start. Require a
  completed verified snapshot reference before apply. Integrate the shared lock/handoff, and
  preserve the original backup error without logging URLs or passwords.

- [ ] **Verify and commit:** PgBouncer inactive with reachable supported database still captures a
  verified backup; unavailable database, pg_dump failure and disk-full all block activation.

### Task 3: Define complete recovery-point manifests

**Files:**

- Create: `specs/install/recovery-point.schema.json`
- Create: `deploy/scripts/lifecycle-recovery.py`
- Create: `tests/build/test_lifecycle_recovery.py`

- [ ] **Step 1:** Capture exact old release/executable tree, units and enabled state, configuration,
  install identity, database schema/version, uploads and vault key. Record digest, size, source
  identity, adapter, timestamp and required restore order for each component. Keep secret bytes in
  restricted files, never the manifest or event stream.

- [ ] **Step 2:** Use the native state root, lock, private creation and atomic finalization from 03.
  Check space before capture. A reference becomes recovery_saved only after all required components
  verify. Track fresh-install recovery separately: record absent/preexisting paths and permitted
  cleanup, never fabricate a pre-install database snapshot.

- [ ] **Step 3:** Implement verify/inspect primitives for retained points and safe pruning
  integrated with references. Do not restore across installation identities or adapters merely
  because versions match. Separate application-owned files from shared host dependencies and record
  actions that cannot be automatically reversed.

- [ ] **Verify and commit:** Corrupt, incomplete, wrong-identity and wrong-schema points are
  unusable; interruption leaves a private partial rather than a selectable point; pruning preserves
  required points.

### Task 4: Establish a quiesced capture protocol

**Files:**

- Modify: `deploy/scripts/lifecycle-recovery.py`
- Create: `specs/install/lifecycle-write-gate.md`

- [ ] **Step 1:** Define `captureRecovery(context)` and `restoreRecovery(reference, context)` native
  requests with validated operation ID and plan digest. Lifecycle capture requires native proof that
  all relevant writers are drained and excluded. In 04, implement a stopped-service capture adapter
  that identifies and stops application writers while retaining database availability. In 05, add
  the durable live gate/drain adapter. Neither path trusts a caller-supplied quiesced flag; missing
  proof refuses before capture.

- [ ] **Step 2:** Specify database/uploads/vault capture ordering and worker/in-flight-write
  handling. Ordinary online backup remains available, but its output must not claim globally
  consistent capture without enforced quiescence. Ordinary direct restore retains its safety
  snapshot and lock.

- [ ] **Step 3:** Define failure behavior before and after restore mutation. Preserve the newer
  safety point and record actual partially restored components; never restart the old binary against
  an unvalidated database.

- [ ] **Verify and commit:** Injected capture tests fail closed when quiescence or drain is missing;
  completed manifests identify consistency mode and restore order. Stopped-service quiescence and
  restore are acceptance gates here; the live gate/drain journey is an additional 05 gate.

- [ ] **Verify and commit:** Native full restore reproduces every captured component and vault
