# npm CLI 03 — Lock, journal and events Implementation Plan

Date: 2026-09-30. Status: **Active — planned; no task started.**

**Goal:** Provide one install-scoped lock, durable operation history and a versioned event stream
shared by npm and direct shell lifecycle entrypoints.

**Architecture:** Root-owned native state is authoritative. Node reads redacted summaries and
coordinates requests; native utilities acquire the lock and write durable state. A lock is held for
the whole transaction, including recovery, rather than reacquired between phases.

**Depends on:** 01; integrate all mutators in 04–07. **Roadmap slices:** 4 and the lifecycle schemas
from 1. **Requirements:** NPM-03, NPM-09, NPM-10.

The [design contract](../docs/design/2026-09-30-v0.4.7-npm-cli-design.md),
[ADR 0006](../docs/adr/0006-npm-installer-cli-for-1.0.md) and
[roadmap](./2026-09-30-v0.4.7-npm-cli-implementation.md) control this work. These are implementation
instructions, not evidence that the behavior shipped. All new paths below are proposed.
File lists are the starting scope: record additional integration/test paths before implementing
a task, and keep the package allowlist and native release inventory synchronized.

## Handoff interfaces

These contracts are proposed here; freeze their field-level definitions in the named
schemas/protocol documents before downstream implementation.

| Interface | Contract / consumer |
|---|---|
| Lifecycle schemas | Plans/results/events/journals version independently; 05–08 consume the schema versions they validate. |
| Native lock context | An inherited locked descriptor plus validated operation context; 04–07 must hold it through every conflicting child action. |
| State utility | Bounded `inspect`, `begin`, `checkpoint` and `list` requests; writes require lock ownership and expected generation. |
| Events | Native child descriptor → coordinator; `--events=jsonl` exposes stderr JSONL, while `--json` emits one final stdout result. |
| Private state | `/var/lib/circuitbreaker-lifecycle`, separate from application data and npm caches; one host-wide lock for supported installs. |

## Scope boundary

No extraction, backup capture, service activation, downgrade selection or visual renderer. Sub-plans
04–07 consume the contracts; 08 consumes events.

### Task 1: Freeze the lifecycle contracts

**Files:**

- Create: `packages/cli/schemas/lifecycle-plan.schema.json`
- Create: `packages/cli/schemas/lifecycle-event.schema.json`
- Create: `packages/cli/schemas/lifecycle-result.schema.json`
- Create: `packages/cli/schemas/operation-journal.schema.json`
- Create: `specs/install/lifecycle-contract.md`

- [ ] **Step 1:** Define schema version 1 and closed validation rules for operation IDs, digests,
  paths, timestamps, adapters, phase transitions and redacted errors. The execution plan includes
  action, source/target identities and digests, compatibility, options, downtime, recovery
  reference, data impact, trust and required acknowledgments. Document canonical serialization and
  SHA256 plan digest; exclude presentation and volatile progress from that digest.

- [ ] **Step 2:** Specify states: planned, staged, verified, recovery_saved, applying, checking,
  committed, recovering, recovered, recovery_required and interrupted. An interrupted record
  preserves the last durable checkpoint. Define allowed transitions, failure outcomes and the
  design's exit codes; native management passthrough retains its codes.

- [ ] **Step 3:** Separate authority from presentation: a user-created plan or event never
  authorizes mutation. Record secret references rather than secret values. Freeze stdout as one
  final JSON result with `--json`; define `--events=jsonl` as stderr JSONL with no mixed diagnostic
  text, and a dedicated child descriptor for native events. In event mode, route diagnostics through
  redacted event envelopes/private logs and final result errors, not unframed stderr. With `--json`
  alone, diagnostics may use stderr; stdout remains one final result.

- [ ] **Verify and commit:** Schema fixtures reject unknown versions, invalid transitions, secret
  fields and malformed identifiers; canonical digest fixtures agree between coordinator and native
  validator.

### Task 2: Implement the shared lock and private state root

**Files:**

- Create: `deploy/lib/lifecycle.sh`
- Create: `tests/build/test_lifecycle_lock.py`

- [ ] **Step 1:** Use `/var/lib/circuitbreaker-lifecycle` as the fixed root-owned state root,
  outside application data and npm caches. Use one host-wide lock for bootstrap and all supported
  installs so identity changes cannot split exclusion; journal records still bind the installation
  identity. Bootstrap state only through native privilege; read-only planning must not create root
  state. Use one stable lock inode and an exclusive advisory lock held by the native transaction
  process. Do not remove the lock file on release or treat a PID file as the lock.

- [ ] **Step 2:** Validate every ancestor, owner and mode; reject symlink, untrusted-owner and
  writable-parent substitutions. Enforce 0700 directories and 0600 state from creation. Lock
  contention returns 10 before stop, backup or mutation. Distinguish permission failure (6) from
  contention. Record owner diagnostics without exposing argv secrets.

- [ ] **Step 3:** Design one explicit internal lock-handoff protocol for nested
  installer/backup/restore calls. Validate the inherited descriptor and operation context; a public
  environment variable claiming lock ownership must never bypass acquisition. A parent crash must
  not release exclusion while a mutating child still runs.

- [ ] **Verify and commit:** Process-based tests prove shell/npm-equivalent callers contend, nested
  calls do not deadlock, stale PID metadata grants no authority, and SIGKILL releases exclusion only
  after all lock-holding mutators exit.

### Task 3: Write atomic journals and safe retention

**Files:**

- Create: `deploy/scripts/lifecycle-state.py`
- Create: `tests/build/test_lifecycle_journal.py`

- [ ] **Step 1:** Implement a narrowly scoped native state utility compatible with the supported
  Python baseline (currently 3.9+). Declare and validate a trusted interpreter before mutation,
  including fresh-host bootstrap. Install the helper, state utility and trust material as a
  root-controlled control plane outside the release tree being replaced; replacing or removing the
  server must not remove its recovery tools. Include their bootstrap/install wiring in the native
  release inventory. Validate requests against the versioned contract without introducing a runtime
  schema dependency. Use same-directory temporary files, flush/fsync, atomic replace and directory
  fsync before acknowledging a checkpoint. Bound record and input sizes.

- [ ] **Step 2:** Persist operation ID, generation/sequence, canonical plan digest, identities,
  artifact digests, adapter, verification evidence, recovery references and mutation checkpoints.
  Reject stale writers and invalid transitions while under the lock. Never interpolate journal text
  into executable shell.

- [ ] **Step 3:** Retention preserves every recovery reference needed by unfinished operations and
  the last successful point. Corrupt or unsupported records are reported as requiring inspection; do
  not silently delete, rewrite or infer success. Keep audit history outside the removal scope by
  default.

- [ ] **Verify and commit:** Fault injection before/after write, replace and fsync produces either
  the old or new valid record; disk-full and stale generation failures block the next mutation.
  Retention cannot orphan an unfinished operation.

### Task 4: Expose history and structured native events

**Files:**

- Create: `packages/cli/src/lifecycle-state.js`
- Create: `packages/cli/src/events.js`
- Modify: `packages/cli/src/main.js`
- Create: `packages/cli/test/lifecycle-state.test.js`
- Create: `packages/cli/test/events.test.js`

- [ ] **Step 1:** Add read-only `history [--json]` with operation outcomes, source/target versions,
  timestamps and recovery availability. Expose a redacted summary through a root-owned, atomically
  written read-only index outside private records, or use an explicitly authorized native read
  request. Do not automatically elevate for history. Never make private recovery files broadly
  readable; return permission 6 when no authorized summary path is available. Reject malformed IDs
  before building paths. Reading history performs no release lookup or repair.

- [ ] **Step 2:** Native events contain schema version, operation ID, monotonically increasing
  sequence, timestamp, phase/state and measured units. Emit events only after the associated durable
  checkpoint where applicable. Bound line length and tolerate partial descriptor reads; invalid or
  out-of-order events cannot change authoritative state.

- [ ] **Step 3:** Wire injected event/result writers into `run(argv, deps)`. Keep forwarded
  management stdout unchanged. Tests pin one final JSON document, no ANSI, stderr event framing and
  zero secrets.

- [ ] **Verify and commit:** History can inspect interrupted/corrupt operations safely; fragmented
  event input is handled and JSON output remains parseable on success, contention and interruption.

### Task 5: Integrate lock boundaries and interruption

**Files:**

- Modify: `install.sh`
- Modify: `deploy/setup.sh`
- Modify: `uninstall.sh`
- Modify: `deploy/scripts/restore.sh`
- Modify: `cb`
- Modify: `deploy/cli/cb`

- [ ] **Step 1:** Inventory every direct-shell mutator, including upgrade, restore, migrate, removal
  and vault recovery; document which management actions can conflict with lifecycle work. Apply the
  shared lock before their first conflicting side effect. Keep cb copies byte-identical and preserve
  standalone operation without Node. Reserve lifecycle transaction checkpoints for the orchestrated
  path; legacy commands may record their actual smaller scope without pretending to be a full
  transaction.

- [ ] **Step 2:** Handle INT/TERM before mutation with safe staging cleanup; after mutation request
  a safe checkpoint and preserve recovery records. A killed process is discovered through durable
  state and real-host inspection, never the last progress line. Ensure traps do not mask the
  original failure or close the lock while a child mutates.

- [ ] **Step 3:** Handle the standalone downloaded installer/uninstaller bootstrap explicitly:
  acquire the same host-wide lock before installing shared utilities or changing services, even when
  deploy/lib is not yet present. Keep any inline lock bootstrap synchronized and tested against the
  installed library. Add shell/native entrypoint contention tests using disposable roots. Do not
  implement recovery decisions here: record recovery_required and defer reconciliation to 06.

- [ ] **Verify and commit:** Every conflicting shell path is locked; mixed entrypoints return 10;
  interruption preserves the last usable checkpoint and native command parity passes.
