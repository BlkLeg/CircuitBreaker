# npm CLI 09 — Packed journeys and governed publication Implementation Plan

Date: 2026-09-30. Status: **Active — scoped implementation landed 2026-10-02; external acceptance gates open.**

**Goal:** Publish the exact accepted CLI tarball in lockstep with server release bytes through
protected, provenance-backed npm promotion and retain verifiable release evidence.

**Architecture:** Extend the existing candidate draft/stable promotion flow. Pack once,
inspect/scan/test those bytes, retain their digest and integrity, then publish/promote without
repacking. Treat GitHub/GHCR/npm publication as a resumable multi-channel operation.

**Depends on:** 01–08 acceptance complete; namespace/protected environment evidence before
publishing. **Roadmap slice:** 10. **Requirements:** NPM-02, NPM-03, NPM-05–15.

The [design contract](../docs/design/2026-09-30-v0.4.7-npm-cli-design.md),
[ADR 0006](../docs/adr/0006-npm-installer-cli-for-1.0.md) and
[roadmap](./2026-09-30-v0.4.7-npm-cli-implementation.md) control this work. These are implementation
instructions, not evidence that the behavior shipped. All new paths below are proposed.
File lists are the starting scope: record additional integration/test paths before implementing
a task, and keep the package allowlist and native release inventory synchronized.

## Scope cut (2026-10-02) — overrides the plan text below

Owner decision: build a solid, simple product first. The npm package is a thin installer/launcher over the existing native scripts, not a full CLI app. Where the text below asks for more than this section, this section wins; unlisted steps are out of scope for 0.4.7. Reuse existing code (`install.sh`, `cb`, `uninstall.sh`, `restore.sh`, `/readyz`) before writing new mechanisms. Docker-mode commands never require sudo. Reviews: at most 2 fix rounds except security findings; Minor findings are deferred, not looped.

**Build:**
- Pack once in the release flow, publish that exact tarball with npm provenance when the stable release is promoted, then fetch it back and compare integrity.
- Unlock npm install docs only after that check passes.

**Cut:** governance/namespace documentation (Task 2 beyond enabling provenance), resumable multi-channel reconciliation (Task 4 beyond a version-exists check), candidate `next` tag channel unless trivially supported, deprecate-plus-patch rehearsal.

## Execution rules

- Implement tasks in order; reconcile consumed interfaces against earlier landed sub-plans first.
- Write meaningful behavioral tests for the acceptance cases, observe the failure, implement,
  then run focused tests and relevant existing contract checks before each task commit.
- Use injected dependencies/temp roots locally and disposable hosts for system journeys.
  Never operate on the developer's installation. Fixtures do not close real-host gates.
- Preserve exact target binding, fail-closed verification, Linux-only claims, no npm hooks,
  secret redaction and unchanged forwarded command contracts. The Node floor and verifier
  dependency are those actually landed by 02. Work that starts before 02 completes
  retains the current supported runtime; reconcile the floor at integration. Do not
  add speculative dependencies.
- Keep package/root/frontend publication policy intact until 09. No public npm install
  advertising before published exact-package acceptance.
- Each task ends with review and a scoped commit using repository prefixes; stage only
  the task's files. Do not sweep another implementer's work into commits.

## Handoff interfaces

These contracts are proposed here; freeze their field-level definitions in the named
schemas/protocol documents before downstream implementation.

| Interface | Contract / consumer |
|---|---|
| Final candidate evidence | Accepted commit/version, exact tgz SHA256 and registry integrity, metadata, SBOM, scans and matrix results. |
| Promotion | Authenticated retained candidate bytes and protected approval; no build/repack or version reuse with different bytes. |
| Reconciliation | Expected channel digests/integrities versus observed publication state; matching resumes, mismatch refuses. |
| Advertising gate | Verified registry existence/provenance/installed bytes and required cross-channel acceptance before docs or `latest` promotion. |

## Implementation and acceptance evidence (2026-10-02)

Additional integration paths: `scripts/ci/cli_publish.mjs`, publication behavioral
and workflow tests, native snapshot routing tests, and package policy guards.
The dedicated CLI is publishable; root/frontend manifests remain private.
Release packs once, checks that exact tarball on Node 24.15.0 and 22.22.2, scans
its dependencies, writes a CLI SBOM, and signs/attests the tarball with server
assets. Protected promotion downloads and revalidates accepted bytes, then uses
npm trusted publishing/provenance. A version already present must have identical
integrity. Publication uses a temporary tag; latest/next promotion follows registry
round-trip comparison and npm signature/provenance verification. Evidence is
attached as npm-publication.json. Public installation documentation stays gated.

The publishing runtime follows the [official npm trusted publishing requirements](https://docs.npmjs.com/trusted-publishers/)
(npm >=11.5.1 and Node >=22.14.0); the workflow pins supported newer runtimes.

Integration review also fixed the stopped-before-move recovery case, restored the
previous install identity during rollback, preserved failure status if journal
commit fails, and resolved native PGDG clients outside PATH. These are necessary
for the packed adapter handoff, not additional product scope.

Local evidence: all 310 CLI tests; exact packed smoke on Node 24.18.0, with 52
locked dependencies and zero install hooks; package/privacy/publication contracts;
native snapshot, retention, backup/restore, shared journal and inline parity tests.
Full validation totals are recorded in the session handoff, not inferred from
plans. Only fixture roots and temporary npm prefixes were used.

Open gates: disposable native install/update/rollback/keep-data reinstall, the
minimum Node/arm64 runner results, configured npm namespace/trusted publisher and
protected release environment, actual registry provenance/round-trip acceptance,
and public docs unlock after those checks. No registry write, release dispatch,
remote push or production-host mutation was performed in this implementation.
Requirement ledger statuses remain unchanged because these external gates have
not passed. Scoped implementation is reviewable; publication acceptance is open.

Recovery adapters and the retention library are now installed in the persistent
control plane and included in the native release/package inventories. This keeps
manual rollback available even when the current release is interrupted or reverted.

Final native lock/journal integration: 287 passed, 4 host/platform checks skipped.
The release-control validator passes with its existing 3 release blockers retained.
Disposable Docker is available, but no signed candidate bundle for this checkout
is present locally; native full-host gates are left for the candidate release job.

Final integrated checks: 310 CLI tests passed; 212 build/native/publication
contracts passed, 1 host check skipped; 287 shared lock/journal checks passed,
4 platform/host checks skipped. Backend snapshot checks passed under the backend
