# npm CLI 07 — Uninstall and purge Implementation Plan

Date: 2026-09-30. Status: **Active — planned; scope cut 2026-10-02 (see below).**

**Goal:** Remove only the identified application scope under the shared lock, retain data by
default, and require a separate exact-scope acknowledgment for npm purge.

**Architecture:** Node builds and confirms a deletion plan; the trusted native helper validates
identity-derived paths and delegates to existing uninstall logic. Direct-shell historical flags
retain their documented semantics.

**Depends on:** 03–05; 06 for partial-removal recovery inspection acceptance. **Roadmap slice:** 8.
**Requirements:** NPM-03, NPM-09, NPM-10.

The [design contract](../docs/design/2026-09-30-v0.4.7-npm-cli-design.md),
[ADR 0006](../docs/adr/0006-npm-installer-cli-for-1.0.md) and
[roadmap](./2026-09-30-v0.4.7-npm-cli-implementation.md) control this work. These are implementation
instructions, not evidence that the behavior shipped. All new paths below are proposed.
File lists are the starting scope: record additional integration/test paths before implementing
a task, and keep the package allowlist and native release inventory synchronized.

## Scope cut (2026-10-02) — overrides the plan text below

Owner decision: build a solid, simple product first. The npm package is a thin installer/launcher over the existing native scripts, not a full CLI app. Where the text below asks for more than this section, this section wins; unlisted steps are out of scope for 0.4.7. Reuse existing code (`install.sh`, `cb`, `uninstall.sh`, `restore.sh`, `/readyz`) before writing new mechanisms. Docker-mode commands never require sudo. Reviews: at most 2 fix rounds except security findings; Minor findings are deferred, not looped.

**Build:**
- npm `uninstall` forwards to the native `uninstall.sh` with its existing flags and prompts.
- `--purge` requires typing `DELETE` interactively, or `--yes` for unattended runs.

**Cut:** identity-derived deletion plans and `--plan` (Task 1 beyond forwarding), `--ack-delete-scope SHA256`, resumable removal and per-action persistence (Task 4), the disposable purge-scope comparison (Task 5 beyond one keep-data reinstall check).

## Handoff interfaces

These contracts are proposed here; freeze their field-level definitions in the named
schemas/protocol documents before downstream implementation.

| Interface | Contract / consumer |
|---|---|
| Removal scope | Canonical identity, exact removed/retained paths and resources, retention policy and scope digest. Exclude operation IDs/timestamps and acknowledgments from the scope digest to avoid circular or unstable consent; bind that digest into the full execution plan. |
| Purge acknowledgment | Separate acceptance of scope digest plus `--yes`, or interactive exact phrase; not an execution authorization token. |
| Native apply | 05 helper recomputes scope under 03 lock and journals actual completed removal steps. |
| Recovery inspection | 06 classifies partial removal from actual remaining state; it never labels deleted data recoverable without a usable point. |

## Scope boundary

CLI package removal is the package manager’s job. Shared dependency deletion, guessed container
cleanup and broad filesystem purge are outside scope.

### Task 1: Define identity-derived removal plans

**Files:**

- Create: `packages/cli/src/uninstall.js`
- Create: `packages/cli/test/uninstall.test.js`
- Modify: `packages/cli/src/main.js`
- Read first: `uninstall.sh`

- [ ] **Step 1:** Inventory actual uninstall behavior and install-mode path sources before changing
  it. Plan executable/release paths, units, configuration, database, uploads, vault key, backups and
  relevant container/volume identities. Distinguish removed and retained items, shared host
  dependencies and npm tool ownership.

- [ ] **Step 2:** Implement `uninstall --plan` with text/JSON and no service stop or privileged
  changes. Default npm uninstall retains data, recovery history and the npm package.
  Unsupported/package-owned modes direct to their authoritative manager rather than deleting guessed
  paths.

- [ ] **Step 3:** Bind exact deletion scope, identity and retention decision to 03 plan digest. Do
  not infer scope from PATH, default container names or untrusted environment.

- [ ] **Verify and commit:** Plan fixtures cover custom directories, missing identity, mode
  ownership and explicit retain/purge scopes; every read-only/cancelled path leaves state untouched.

### Task 2: Implement purge consent before service stop

**Files:**

- Modify: `packages/cli/src/uninstall.js`
- Modify: `packages/cli/src/help.js`
- Modify: `packages/cli/test/uninstall.test.js`

- [ ] **Step 1:** Interactive purge requires explicit selection and the exact text `DELETE
  circuitbreaker` entered in an initially empty prompt after displaying deletion scope. Empty input,
  wrong text, EOF or cancel refuses before service stop.

- [ ] **Step 2:** Define unattended npm contract as `--purge --yes --ack-delete-scope SHA256`, where
  SHA256 is the current displayed canonical removal-plan scope digest. Bind all deletion paths and
  identity into that digest and document its validity/revalidation. Generic `--yes` alone never
  authorizes deletion; changed scope requires a new plan acknowledgment.

- [ ] **Step 3:** Reject contradictory retention/purge flags and stale acknowledgments with
  usage/preflight errors. Require `--yes` for noninteractive keep-data removal too. `--json`
  controls output, not consent or TTY detection: it may coexist with an interactive prompt on the
  designated control stream. With `--events=jsonl`, prompts must use a separate TTY and leave stderr
  pure JSONL; without a usable TTY or required flags, return structured refusal before stop.

- [ ] **Verify and commit:** PTY and noninteractive tests prove initial prompt is empty, exact text
  required, digest changes invalidate consent and cancellation stops before any mutation.

### Task 3: Apply safe removal through the helper

**Files:**

- Modify: `deploy/scripts/lifecycle-helper.sh`
- Modify: `uninstall.sh`
- Modify: `cb`
- Modify: `deploy/cli/cb`
- Create: `tests/build/test_lifecycle_uninstall.py`

- [ ] **Step 1:** Revalidate source identity and scope under root and 03 lock. Reject filesystem
  roots, ancestor-of-install broad deletes, symlink/ancestor swaps, shared dependencies and
  unexpected mount boundaries. Use validated native path operations; prevent verification/deletion
  races rather than relying only on an earlier realpath check.

- [ ] **Step 2:** Add an internal helper context that passes confirmed retain/purge decisions
  without repeated prompts and records each destructive step. Preserve direct-shell `--purge` and
  `--keep-data` semantics and tests; document that npm purge has stronger separate acknowledgment.
  Direct shell paths also use the shared lock.

- [ ] **Step 3:** Leave npm tool installed. Retain journal/log/recovery state outside normal
  deletion scope; if explicitly purging recovery assets, preserve enough protected audit state to
  explain completion/interruption and mark recovery unavailable accurately.

- [ ] **Verify and commit:** Mixed shell/npm removal contends; malicious paths and substitution
  races refuse before deletion; only declared application files disappear; cb copies remain
  byte-identical.

### Task 4: Handle interrupted removal and recovery availability

**Files:**

- Modify: `deploy/scripts/lifecycle-helper.sh`
- Modify: `deploy/scripts/lifecycle-recovery.py`
- Modify: `packages/cli/src/uninstall.js`

- [ ] **Step 1:** Persist each completed removal action; interruption reports actual remaining
  services/files/data and whether reinstall or recovery is possible. Do not claim purge is
  reversible after deleted recovery material.

- [ ] **Step 2:** For keep-data removal, verify retained identity/config/database/uploads/vault
  material can support reinstall. Integrate 06 recovery inspection for partially removed installs,
  refusing blind restart when files/data are missing.

- [ ] **Step 3:** If backup is required by the chosen removal plan, failure blocks removal. Do not
  silently create an unauthorized database restore or delete a retained recovery point.

- [ ] **Verify and commit:** Kill tests after stop, unit removal, executable removal and data
  deletion produce truthful journals and actionable results.
