# npm CLI 06 — Downgrade, rollback, recover and CLI update Implementation Plan

Date: 2026-09-30. Status: **Active — planned; scope cut 2026-10-02 (see below).**

**Goal:** Expose certified older-release transitions, retained-point rollback and evidence-based
interruption recovery, with explicit data-loss acknowledgment; update the CLI independently.

**Architecture:** A pure selector builds digest-bound plans from authenticated compatibility
metadata and verified recovery manifests. The same native transaction machinery applies them.
Recovery inspects real files, services and database schema before deciding any action.

**Depends on:** 05; historical transition certification may begin earlier. **Roadmap slices:** 7 and
the older-release audit from 1. **Requirements:** NPM-03, NPM-09, NPM-11.

The [design contract](../docs/design/2026-09-30-v0.4.7-npm-cli-design.md),
[ADR 0006](../docs/adr/0006-npm-installer-cli-for-1.0.md) and
[roadmap](./2026-09-30-v0.4.7-npm-cli-implementation.md) control this work. These are implementation
instructions, not evidence that the behavior shipped. All new paths below are proposed.
File lists are the starting scope: record additional integration/test paths before implementing
a task, and keep the package allowlist and native release inventory synchronized.

## Scope cut (2026-10-02) — overrides the plan text below

Owner decision: build a solid, simple product first. The npm package is a thin installer/launcher over the existing native scripts, not a full CLI app. Where the text below asks for more than this section, this section wins; unlisted steps are out of scope for 0.4.7. Reuse existing code (`install.sh`, `cb`, `uninstall.sh`, `restore.sh`, `/readyz`) before writing new mechanisms. Docker-mode commands never require sudo. Reviews: at most 2 fix rounds except security findings; Minor findings are deferred, not looped.

**Build:**
- `rollback`: restore the release moved aside by the last update and, if the user confirms, the pre-update backup via `cb restore`.
- Interrupted operations show in `history` (03) with the exact manual command to run; no automated reconciliation.

**Cut:** `downgrade` (Tasks 1–2) and certified transitions, retained-point selection by operation ID, `recover` (Task 4), `cli update` (Task 5 — document `npm i -g @blkleg/circuitbreaker@VERSION` instead). Real-transition journeys (Task 6) shrink to one update-then-rollback run.

## Execution rules

- Implement tasks in order; reconcile consumed interfaces against earlier landed sub-plans first.
- Write meaningful behavioral tests for the acceptance cases, observe the failure, implement,
  then run focused tests and relevant existing contract checks before each task commit.
- Use injected dependencies/temp roots locally and disposable hosts for system journeys.
  Never operate on the developer's installation. Fixtures do not close real-host gates.
- Preserve exact target binding, fail-closed verification, Linux-only claims, no npm hooks,
  secret redaction and unchanged forwarded command contracts. The Node floor and verifier
  dependency are those actually landed by 02. Work that starts before 02 completes
  retains the current supported runtime; reconcile the floor at integration. Do not
  add speculative dependencies.
- Keep package/root/frontend publication policy intact until 09. No public npm install
  advertising before published exact-package acceptance.
- Each task ends with review and a scoped commit using repository prefixes; stage only
  the task's files. Do not sweep another implementer's work into commits.

## Handoff interfaces

These contracts are proposed here; freeze their field-level definitions in the named
schemas/protocol documents before downstream implementation.

| Interface | Contract / consumer |
|---|---|
| Certified transitions | Authenticated source/target schema and artifact digests, platform, adapter and data policy; 05/06 enforce eligible transitions. |
| Recovery selection | Exact operation/recovery ID and verified manifest digest bound into the execution plan. |
| Reconciliation | Observed release/unit/schema/identity/gate state plus last durable checkpoint → allowed actions or manual intervention. |
| Tool update context | Validated recorded npm owner/prefix/manager/launcher; independent of server lifecycle transactions. |

## Implementation evidence (2026-10-02)

Additional integration path: `deploy/scripts/rollback-release.sh` (shipped by the
existing native deploy/scripts inventory). npm rollback validates the trusted
native adapter and requires ROLLBACK/RESTORE or explicit --yes. Data replacement
also requires --restore-data. The adapter holds the shared lock, snapshots current
state using the current builder, optionally runs cb restore on the pre-update
snapshot, restores the retained release, and checks readiness/version. Failed
rollback retains actual release and snapshot state for manual inspection.
Interrupted update history gives the exact native rollback command and cb doctor.
Downgrade, recover and cli update remain explicit unsupported commands.

Fixtures and packed checks validate dispatch and acknowledgement boundaries;
a real update-then-rollback host journey remains an open release gate.
