# Map design capability audit

Audited 2026-09-29 against the working tree. This is a source audit, not a runtime
or performance certification. Existing uncommitted map work is included.

| Proposed capability | What is already present | Actual redesign opportunity |
| --- | --- | --- |
| Real-time topology and telemetry | `MapWorkspace.jsx` subscribes to node movement, cable additions/removals, and status changes. `useMapRealTimeUpdates.js` consumes telemetry pushes and falls back to batched polling. | Improve how updates and connection/sample state are communicated. Do not present streaming or fallback as new. |
| Health indicators | `CustomNode.jsx` has effective status, telemetry rings, latency, temperature/power, CPU/RAM badges, and connection interaction states. | Redesign the node visual grammar and legibility. Map-wide counts would be an additional aggregation, not a new health system. |
| Selected-node inspector | `Sidebar.jsx` already shows identity, system info, model/override/telemetry status, timestamps, monitoring, telemetry, relationships, documents, and HUD navigation. | Recompose existing information into a precise inspection surface; an inspector itself is not new. |
| Hover telemetry | `TelemetrySidebar.jsx` already has CPU/memory/disk meters, network rates, uptime, Proxmox/cluster/storage details, and service discovery data. | Upgrade the existing hover surface and provide optional deeper chart inspection. Do not describe hover metrics as new. |
| Relationship inspection | `buildRelatedNodes` and `Sidebar.jsx` show direction, relation, neighbor identity/type/address. | Map-local navigation/highlighting could improve this. Current relationship rows are informational, not a neighborhood isolation mode. |
| Search | The global navigator uses `useNavigatorSearch.js` to search pages/settings/actions and remote entities. The map has environment/tag/type/role filters. | Finding and centering a node within the current graph is a narrower potential extension. Global search must not be reinvented as a new app capability. |
| Grouping and zones | Map layout presets, grouping, cloud view, boundaries, zone presets, labels, and visual lines exist. | Upgrade region headers, equipment grouping, density and edge routing. Zones and multiple layout choices are not new. |
| Bandwidth and animated edges | `CustomEdge.jsx` already shows explicit configured bandwidth and renders connection particles. Particle speed uses bandwidth, including a fallback; it is not measured traffic. | Improve connection hierarchy and labels. Never call particles live traffic or convert link capacity into utilization. |
| Zoom, fit, fullscreen | React Flow controls, viewport persistence/restoration and browser fullscreen already exist. | Improve placement and presentation of navigation tools. A chrome-free wallboard would extend fullscreen rather than introduce it. |
| Reconnect and freshness | Shared `ConnectionStatus.jsx` reports SSE/discovery reconnection. Topology/telemetry hooks expose their own connection state. The inspector displays telemetry and monitor timestamps. | Consolidate map-specific connection state and make sample age/staleness clearer. A global reconnect indicator is already present. |
| Security overlays | `PrivacyScoreWidget.jsx` and `HostileNetworkBanner.jsx` already surface privacy score and actual warning/critical alerts. | Integrate these existing signals into the map composition instead of adding a fictional SOC feed. |
| Recent activity | `RecentChanges.jsx` already fetches `adminApi.recentChanges(10)` and displays recent entity changes with inventory navigation. Topology events are consumed by the map, but the audited map does not render a bounded topology event rail. | A map-scoped, click-to-focus rail would extend existing activity presentation, not introduce app-wide recent changes. A correlated incident timeline needs separate data contracts. |
| CPU/history charts | The map currently uses numeric readings and meters. The entity telemetry endpoint supplies up to 20 recent metric rows, not 20 samples per metric. `AgentTelemetryTab.jsx` already renders synchronized multi-metric history, local scales, a shared pointer/keyboard cursor and history ranges. `LatencyChart.jsx` already renders monitor history. | Reuse the app's established analysis language and available histories. Map integration and reusable TypeScript chart modules are new work; basic history charting in the app is not. |
| Minimap, neighborhood mode, semantic zoom | No minimap or neighborhood isolation mode was found in the audited renderer/workspace. `CustomNode.jsx` already reduces ordinary nodes to 16px markers below zoom 0.4. | Minimap and neighborhood focus would be additions; semantic zoom already has a basic implementation. All are secondary to the visual overhaul. |

## Correction to the first proposal

The first proposal made existing health, inspection, telemetry, grouping and
navigation capabilities sound novel, and its illustrative CPU chart was weaker
than the existing agent telemetry workbench. The revised effort is a visual
upgrade of the operational map. Added interaction modes are optional follow-on
work, not the rationale for the redesign.

The original visual reference (`New Map.webp`) is a historical 0.2.2 capture,
according to the screenshot manifest. It is not a current-app baseline. The
user's latest correction explicitly preserves current map node shapes, branded
SVGs and vendor imagery. The rectangular equipment tiles from the console draft
are suitable only for an optional structured connection walkthrough.
