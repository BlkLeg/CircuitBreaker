# npm CLI 05 — Install, update and native mutation helper Implementation Plan

Date: 2026-09-30. Status: **Active — scoped implementation landed 2026-10-02; external acceptance gates open.**

**Goal:** Execute a confirmed, digest-bound native install/update using the already verified
immutable release; commit success only after health, version, schema and identity match.

**Architecture:** Node plans and presents without elevation. An installed, root-controlled native
helper validates a narrow request, copies inputs to root-controlled storage, independently verifies
them and owns the lock through backup, apply, health and recovery. Existing installer logic runs
only through target-bound local inputs.

**Depends on:** 02–04 implementation and native acceptance complete; add live gate integration to
04’s stopped-service capture contract. **Roadmap slices:** 3 privilege/extraction boundary and 6.
**Requirements:** NPM-03, NPM-09, NPM-10, NPM-11.

The [design contract](../docs/design/2026-09-30-v0.4.7-npm-cli-design.md),
[ADR 0006](../docs/adr/0006-npm-installer-cli-for-1.0.md) and
[roadmap](./2026-09-30-v0.4.7-npm-cli-implementation.md) control this work. These are implementation
instructions, not evidence that the behavior shipped. All new paths below are proposed.
File lists are the starting scope: record additional integration/test paths before implementing
a task, and keep the package allowlist and native release inventory synchronized.

## Scope cut (2026-10-02) — overrides the plan text below

Owner decision: build a solid, simple product first. The npm package is a thin installer/launcher over the existing native scripts, not a full CLI app. Where the text below asks for more than this section, this section wins; unlisted steps are out of scope for 0.4.7. Reuse existing code (`install.sh`, `cb`, `uninstall.sh`, `restore.sh`, `/readyz`) before writing new mechanisms. Docker-mode commands never require sudo. Reviews: at most 2 fix rounds except security findings; Minor findings are deferred, not looped.

**Build:**
- `install`, `update`, `update --check`: Node resolves and verifies the release (02), then runs `sudo bash install.sh --local-bundle <verified tarball>` with argv arrays. `install.sh` already verifies the signature and takes the lifecycle lock (03).
- Update sequence: `cb backup` → move the old release aside → install → `/readyz` + version match → done. On failure: put the old release back, restart, and print the backup path and the `cb restore` command.
- Set the entrypoint's "changes began" flag at `applying` if a journal operation is recorded (03 amendment).
- Lock the deb/rpm/apk preinstall/postinstall scriptlets with the existing library (open item from 03 §11) — native paths only.

**Cut:** the custom privileged request protocol and re-copy/re-verify into root storage (Task 2 beyond the sudo call), the live write gate and worker drain (Task 4 — stopping the service is the write block), schema/identity commit gates beyond health + version.

## Handoff interfaces

These contracts are proposed here; freeze their field-level definitions in the named
schemas/protocol documents before downstream implementation.

| Interface | Contract / consumer |
|---|---|
| Verified staging from 02 | Exact target, staged paths, digests and verification evidence; online signed provenance must be retained in a re-verifiable form. Extend 02’s boolean/status-only verifier interface in Task 2 without weakening its verification policy. |
| Execution plan | Canonical 03 plan plus source identity, target, options, recovery policy and acknowledgments; native helper recomputes its digest. |
| Native helper | Bounded request plus copied immutable inputs; emits 03 events and one authoritative result, and owns the transaction lock. |
| Write exclusion | Durable gate generation plus drain/stop proof; 04 captures under it and 06 restores/applies under it. |
| Launcher registration | Absolute path, ownership and npm install context; 06 CLI update validates it without changing server identity. |

### Task 2: Implement the trusted privilege boundary

**Files:**

- Create: `deploy/scripts/lifecycle-helper.sh`
- Create: `packages/cli/src/native-helper.js`
- Create: `packages/cli/test/native-helper.test.js`
- Create: `tests/build/test_lifecycle_helper.py`

- [ ] **Step 1:** Define a fixed request protocol using 03 schemas; bound size and allowlisted
  actions/options. Locate the helper from trusted installed metadata or provision it for fresh
  install through a documented independently verified bootstrap boundary. Never execute a
  user-writable script under sudo just because Node verified its path earlier. Specify and test the
  fresh-host trust bootstrap before enabling npm `install`: identify the authenticated helper
  distribution, pinned trust source, explicit privilege consent and atomic root-owned installation.
  A user-owned npm helper path is not a trusted bootstrap. Until that boundary is implemented and
  reviewed, refuse fresh-host execution with the direct-shell prerequisite; keep the fresh-host npm
  installation gate open rather than claiming it complete.

- [ ] **Step 2:** Elevate only this helper, never npm or the Node frontend. Use argv arrays and a
  controlled environment; reject command strings and privilege-related injected env. Acquire 03 lock
  and validate plan digest, identity, caller/context, owners and ancestors before accepting inputs.

- [ ] **Step 3:** Copy staged tarball, sums/signature and required verification evidence into
  private root storage without following mutable symlinks. Verify the copied bytes independently
  against root-controlled trust policy and exact planned target; validate retained provenance
  evidence/claims rather than accepting a caller's boolean. Add an explicit evidence handoff from
  02’s verifier and specify a native verification mechanism without running Node as root; this is a
  blocking Task 2 design/acceptance requirement. Document offline policy consistently with 02:
  signed air-gap bundles report provenance skipped, never verified, and make zero requests.
  Revalidate archive safety under privilege before extraction; fail if policy/trust material cannot
  be trusted.

- [ ] **Verify and commit:** Swap-after-plan, symlink, writable helper, tampered evidence, changed
  identity and digest mismatch fail before stop; missing privileges returns 6. A hostile caller
  cannot authorize arbitrary root execution.

**Files:**

- [ ] **Step 1:** Audit all actual write paths: authenticated/public HTTP, WebSocket, workers,

- [ ] **Step 2:** Reject new writes and drain in-flight writers before the 04 recovery capture.
  Reads/diagnostics expose actual maintenance state separately from readiness. Bound drain timeout;

- [ ] **Step 3:** Older running releases may not implement the live gate. Use 04’s stopped-service
  adapter to exclude their writers externally, and keep target external writes blocked until commit.

  protected the pre-upgrade snapshot. Permit narrowly authorized migration/check activity without

  committed-but-still-gated resumes gate release, unfinished operations remain gated. Test alternate
  and background paths rather than only the middleware.

- [ ] **Verify and commit:** Writes attempted during capture/apply/checking are rejected or drained;
  startup cannot bypass the gate; crash between commit and gate release converges safely. Recovery

## Implementation and handoff (2026-10-02)

Additional integration paths: `deploy/lib/release-retention.sh`, both `cb` copies,
`packaging/preinstall.sh`, `packaging/postinstall.sh`, inline synchronization and
its tests, `packages/cli/src/events.js`, and the lifecycle journal contract.

Install/update apply is wired through verified staging and argv-based native bash
execution. Explicit `--yes` follows plan review; update checks create no operation.
Same-version apply is a verified no-op and older-target apply refuses. Native
install owns the lock through old-runtime full snapshot, writer stop, release move,
apply, readiness/version checks, and an in-process release recovery attempt.
Failures preserve snapshots and failed release trees; data restoration is manual.
The installer emits one bounded authoritative final result, consumed independently
of events. Package pre/post scriptlets share the lifecycle lock.

Contract amendment: legacy records may now enter checking/recovering and finish
recovered, without claiming a digest-bound full transaction or recovery manifest.
The original interruption rule is retained, and applying marks changes begun.

Validation so far: 6 install/update behavioral tests, 87 existing CLI stream/plan
checks, and 75 native retention/package/inline checks pass (one existing host-only
check skipped). Disposable-host install/update and migration fault journeys remain
open; fixtures do not establish host certification or production acceptance.
